## 0. Status of the guide's deliverables
# - Migration 20260925110000_records_ops (+ rollback): releases, tracks (FK releases, FK suno_takes), rights_splits
#   (FK tracks, payee, percentage).
#   Split integrity is a DB rule (user decision D1, ARCHITECTURE F31):
#   - every committed split set sums to exactly 100 (a deferred constraint trigger, for every role, the owner
#     included);
#   - an unassigned share is an explicit payee-null row that the sum counts;
#   - a release can't enter scheduled/released while any track has no set or an unassigned share.
# - Catalog agent, "Knowledge/Execution hybrid" (F10, user decision D2: split + workflow):
#   records-catalog-lookup (Knowledge) → records-catalog (Execution), in records/workflows/register-track.workflow.yaml.
#   A finished take (Phase 9 suno_takes) is registered with ISRC/UPC present but nullable until assigned.
# - Rights agent: records-rights-splits (Governance, deterministic). It checks four rules, each reported, and flags every
#   unassigned percentage. A flag is a successful run whose flags are data.
# - Release-calendar agent: records-release-calendar (Execution, D3). Scheduling only, and only on a passing Rights check
#   for the same release. records/workflows/schedule-release.workflow.yaml runs Rights first. The DB guard re-checks the
#   splits and verifies the Rights run the release records (a forged pass gains nothing).
# - The split-sum constraint test and proof: tests/phase-13/records-db.test.ts (section 1) and the direct-insert
#   attempts in section 2c, 2f and 2h.
# - 5-bullet handoff for Phase 14: docs/handoffs/PHASE-13.md.
