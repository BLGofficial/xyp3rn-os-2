## 0. Status of the gate (PLAN.md §5 Phase 3: "every generation attempt can be traced to the exact lyric, style, tags, workflow version, and resulting audio")
# - generation_attempts names, per submission, the exact lyric, style recipe and meta-tag set versions (ids and versions
#   from the package's sources), the workflow run that built the package with its name and spec sha256, and its takes;
#   generation_takes names each take's Vault file and the audio's sha256, and the owner's current rating.
# - Every attempt is traced by construction: the DB refuses a submission whose package isn't a x3lius.suno-package/v1
#   written by x3lius-suno-package, built in a successful workflow run, with every version it names approved (S4), and
#   whose recorded prompt isn't the package's own. Section 2i: 0 untraced attempts.
# - Decisions S1–S4 (F40): style recipes and tag sets are artifact lineages approved like lyrics; the code labels are the
#   default tag set's v1; the handoff is a package (JSON + copy-paste text) and the result a Vault take; approval is a
#   hard gate at submit, asked before any adapter call (a draft never reaches the sunoapi reseller: tests/aos-03).
# - Shown three ways: tests/aos-03/idea-to-take.test.ts, the CLIs (section 2), the browser (section 3). The trace
#   survives xyp-vault-export/v1 into a fresh database (2j and the gate test).
# - Written after the features, not first: the gate test and the web smoke extension (integration over agents already
#   built), so they were never red. The DB, agent, package-export and web loader/ops tests were red first.
# - Not run live (F41): recipeFrom on a formula a model wrote (no LLM key), and a package under a canonical Suno limit
#   (no suno.limit.* claim is admitted); both proven on fixtures (a fixture formula; a unit test over claim items).
