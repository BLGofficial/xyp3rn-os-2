AOS-01 — Creative Vault + song schema: proof (2026-09-25)
Produced with the repo's own commands against the local Postgres. Every DB test runs in its own throwaway database. Section 2
runs the real CLIs against two throwaway databases (xyp_proof_aos01_a, xyp_proof_aos01_b, dropped afterwards) with temporary

## 0. Status of the gate (PLAN.md §5 Phase 1: "every asset has an ID, owner, source, and linked creative object")
# - Songs (A1): a stable id with append-only revisions (derived, gap-free numbers) and typed links: exactly one of a lyrics
#   lineage root, a Vault file, a take, a track, a research question. Unlink is a retraction row; history is kept.
# - Vault files: `sources` rows with storage/media_class/language and the agent run that added them; bytes in a
#   content-addressed store (.vault/<sha256>, XYP_VAULT_DIR) verified on every read; text for documents and lyric sheets.
# - Owner writes through three deterministic agents (A2): vault-curator, records-songs (Execution), x3lius-lyric-editor
#   (Creative). Every change has its agent_runs row. Approval is the owner's decision (xyp_decide_artifact, service_role).
# - Search (A3): one Context Engine, two corpora. The knowledge corpus every agent grounds on is unchanged by Vault rows
#   (pinned item for item, generation included); `corpus: 'vault'` finds lyrics, files and findings next to knowledge.
# - Export (G5): xyp-vault-export/v1. A → B → re-export is byte-identical; re-import is a no-op; conflicts refuse it all.
# - UI (A4): apps/web (Next.js 14) on 127.0.0.1 behind XYP_WEB_TOKEN: /vault, /vault/files/[id], /vault/lineages/[id],
#   /ingest, /songs, /songs/[id]. Reads as xyp_web (read only); writes through dispatch and the owner's decision.
# - Not proven live: an MP3 upload (no MP3 exists in the repo; a generated WAV stands in, same code path: `audio`, no text).
