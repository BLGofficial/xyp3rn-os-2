## 0. Status of the gate (PLAN.md §5 Phase 2: "a song can move from idea to release with its creative history and metadata intact")
# - One song, idea → writing → producing → releasing → released, every step an agent run or a Records workflow; no row
#   inserted by hand (tests/aos-02/idea-to-release.test.ts, section 2 through the CLIs, section 3 through the browser).
# - Metadata (B1–B4): people with aliases (one case-insensitive namespace) and credits by role on songs and tracks; tasks
#   with events; platform links from a fixed list, host-checked; artwork from a Vault image (newest is current); delivery
#   events per distributor; a track from a Suno take or a Vault audio file (ISRC compared per recording).
# - The Command Center reads catalog_checks: blockers (no tracks, no artwork, no splits, an unassigned share) and warnings
#   (no UPC/ISRC/credits, scheduled with no delivery, released with no link, lyrics not approved, song status behind/ahead).
#   The checks clear as the data arrives; at the end none is left.
# - History intact: every revision, link, lyric version and decision; both split versions; the retracted credit and link;
#   the artwork and delivery events; the task's events; the recording traced to its Vault file, sha256 and run.
# - UI: / (dashboard), /releases, /releases/[id], /people, /tasks, and the /songs/[id] additions. Reads as xyp_web
#   (read only); writes through dispatch and the Records workflows.
# - Written after the features, not first: the gate test (an integration gate over agents already built), so it was
#   never red. The DB, agent, export and web loader/ops tests were red first.
# - Known limit (F37): a released release can't be exported for a restore yet (AOS-08); the gate asserts the refusal.
