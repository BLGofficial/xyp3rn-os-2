# Handoff: Mercury voice (Wispr Flow dictation + local Kokoro speech)

**Scope delivered:**
- Wispr dictation into an editable Mercury message box.
- Explicit submission through the existing OS runtime.
- Optional spoken replies from local Kokoro.

## Startup and shutdown (PowerShell, repository root)

```powershell
pnpm voice:start          # start/reuse xyp3rn-pg and xyp3rn-kokoro, wait until healthy
pnpm voice:status         # prerequisites and health; config names only
pnpm build; pnpm start    # Mercury production (or: pnpm dev)
# ... use http://127.0.0.1:3000 ...
# Ctrl+C in the Mercury terminal
pnpm voice:stop           # stops xyp3rn-kokoro (Postgres left running)
docker stop xyp3rn-pg     # only if nothing else needs the database
```

## Measurements (details in PLAN.md)

- **Request → result (real RECORDS run):** cold 58.2 s; warm 22.5–48.1 s. Bound by the LLM
  (OpenRouter free model).
- **Synthesis via the bridge, ~4.5 s of audio:**
  - cold 2.59 s (first after server start), 1.81 s (first after Kokoro restart);
  - warm 1.62–1.70 s.
- **Kokoro container → healthy:** 54 s on first creation; 14.5 s on restart.
- **Result rendered → first audible playback (browser, short reply):** 1.77–1.91 s. This is not a
  human-perceived measure.
- **Owner's real Wispr turn:**
  - Paste → Send: 1.1 s.
  - Send → result: 46.4 s. Of that, 46.0 s was inside the `x3lius-lyrics` agent run (context
    assembly plus the `openrouter:nvidia/nemotron-3-ultra-550b-a55b:free` call, about 5,000
    tokens).
  - Result → first audio: 2.9 s.
- **Wispr latency:** not measured. The browser cannot observe Wispr's recording.

## Remaining limitations

- **Request status lives in memory in one Next process.** A restart forgets in-flight requests (the
  UI says so; the DB runs remain). It doesn't work with multiple server instances.
- **Links:** approvals deep-link to the inspector. Runs and artifacts have no entity pages, so they
  show as ids plus Live Events.
- **Permissions:** there are no per-domain permissions. `runtime.execute` is the execution gate,
  and agent tools are still authorized per agent class in `dispatch`.
- **Replies are deterministic summaries,** not full research findings or artifact bodies.
- **Voices:** a supported allowlist of 6; Kokoro reports 72.
- **Tokens:** no revocation CLI; sign-out clears only the browser cookie.
- **Scratchpad scripts:** the validation harness scripts live outside the repo.
- **Validation data:** the users `voice-validation-{operator,viewer,approver}` and two
  `[FIXTURE] release` rows (now scheduled) were added to the local database.
