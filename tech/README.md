# tech/ — TECH

Products, Audio Tools (TRACE), AI Systems, R&D (Phase 14). Contract: [docs/ARCHITECTURE.md](../docs/ARCHITECTURE.md#tech--xyp3rn-tech).

- `trace/analysis.ts`: `trace.analysis/v1`, the TRACE boundary contract (Phase 11, ARCHITECTURE F24). X3LIUS Mix/Master reads it, and Phase 14 implements it. It is never edited in place.
- `trace/report.ts`: `trace.report/v1`, the answer TRACE receives (Phase 14). It is the one definition of a check; Mix/Master and the mix report artifact import it.
- `trace/schemas/*.schema.json`: the contract as JSON Schema for the plugin, generated by `pnpm trace:schemas` and never hand-edited (drift-tested).
- `trace/server.ts`, run by `pnpm trace:serve`:
  - `POST /v1/trace/analyses` (a `trace.analysis/v1` body, optional `?takeId=`) → `workflows/trace-intake.workflow.yaml` → `trace.report/v1`;
  - `GET /v1/trace/analyses/:id` and `GET /v1/trace/health`;
  - 127.0.0.1, with `Authorization: Bearer $XYP_TRACE_TOKEN`.
- `trace/intake.ts` + `trace/tools.ts`: `tech-audio-tools` (Execution) records the analysis and links its report (`trace.write`, `xyp_trace_intake`).
- `r-and-d/`: `tech-r-and-d` (Planning, LLM).
  - It reads the Frontier Scanner's uncited evidence (`research.read`).
  - Code verifies each proposal and writes `rd_backlog` (`plan.write`, `xyp_planner`).
  - The DB queues each item for a human (`pnpm gate queue` / `pnpm gate decide`).
- `tech.manifest.yaml`, `tech-system.ts`, `entrypoint.ts`: the four components (Products, Audio Tools, AI Systems, R&D), admitted through the gate, with one agent each. They are the `pnpm ask` entrypoint for TECH.
